# Mac steps: `koan autofill`, and the agent never reads what it fills (design sections 4.5 and 7.0)

For the Mac loop and the hands-on tester. DCHECK build, a fresh test profile, Agent ready on. The scripted part is
`scripts/mac/suite.sh --only agent_autofill` (someone presses Allow when it pairs and when koan-relay starts); its test
data (an address, Visa's test card 4111…1111, a login for the fixture server) is made in the test profile through
chrome://settings and never touches the user's profile. The rest is by hand, with `koan` from
`Koan.app/Contents/Resources/bin/` paired as "koan suite", on local fixture pages (`python3 -m http.server` serving the
forms in `scripts/e2e/agent_autofill.mjs`) or on a test site of your own. Use test data only.

| # | Do | Expect |
|---|---|---|
| T-fill-1 | `koan open` an address form, `koan snapshot <tab> --interactive`, `koan autofill <tab> @<name field> --list` | Numbered labels as the dropdown shows them ("Ada Lovelace · 12 Main St, …  [address]"). No popup opens in the agent's tab, and none over your work. |
| T-fill-2 | `--pick 1` | "ok: filled address …"; the snapshot shows the filled address. The audit log (Settings > Agent Control > Activity) has a `Koan.autofill` line with "address <label>", no values. |
| T-fill-3 | A login form with a saved test login: `--list`, then `koan act <tab> autofill @<email> 1 click @<Sign in>` | The label is "user (saved password)", never dots or the password. The snapshot shows the password field as "•••• (filled)". The form submits and the site signs in. |
| T-fill-4 | While the password is in the page: `koan agent-browser eval 'document.querySelector("input[type=password]").value'` (or any `Runtime.evaluate`) | Refused: Koan.secretField. `koan act <tab> fill @<another field> "x"` still types ("ok: typed (…not cleared first or read back)"); clicks and Enter work. After the page navigates, script works again. |
| T-fill-5 | A card form, with Settings > Autofill > Payment methods > "Use Touch ID to fill" **off**: `--pick 1` | Filled; the snapshot reads "•••• (filled)" for the number (and the CVC if any); `koan screenshot` says "the card fields Koan filled are hidden in it" and the image shows solid boxes over them (also with `--clip`, `--size full`, a page scrolled down, and a payment form in a cross-origin iframe, where the whole frame is boxed). `koan agent-browser` screencast frames stop while it is filled. Print (`Page.printToPDF`) is refused. |
| T-fill-6 | The same with "Use Touch ID to fill" **on** (or a Google Pay card that needs its CVC) | The pick prints "Koan.userNeeded: Chrome asks the user to verify this card"; the pill reads "koan suite needs you to verify a card" with Open / Dismiss, over no other window. Open: the tab comes forward and Chrome asks for Touch ID (or the CVC) there; once you verify, the form fills and `koan watch` shows Koan.userNeededDone. Dismiss: nothing is filled. The agent letting go of the tab (`koan end`) drops the prompt. |
| T-fill-7 | A login form whose `action` is another site | `--pick` fails with Koan.offSite; nothing is filled. A login saved only for a related site (a grouped affiliation match, which Chrome confirms with a popup): Koan.offSite, and no popup shows. |
| T-fill-8 | Settings > Agent Control > What agents can use: untick Addresses and cards, then Saved passwords | `--list` fails with Koan.autofillOff on the address/card form, then on the login form. Tick them again: suggestions come back. |
| T-fill-9 | An agent tab on a site with a saved login, loaded fresh | Nothing is filled or previewed on load (no yellow fields); the login waits for `koan autofill`. `navigator.credentials.get({password: true, mediation: "silent"})` from the page gets nothing (no auto sign-in in agent tabs). In one of your own tabs both still work as before. |
| T-fill-10 | Pause the agent's tab (type in it), then `koan autofill <tab> @field --list`; and on a readable tab of yours (`koan take-over` declined to drive) | Koan.paused; Koan.notPermitted. A tab showing a certificate warning: Koan.interstitial. |
| T-sec-1 | After a pick of a login and a CDP click in the page (`koan act <tab> click @<page>`), read the password with page script (the fixture's own `<script>`, or the browser test `KoanAgentAutofillBrowserTest.ALoginAndTSec1`) | The page can read it (Chrome sets the real value when a login is picked, as for the user, so that the page can send it). The agent never gets it: script in that frame is refused (T-fill-4), the field reads "•••• (filled)", and the scrubber replaces any copy (the page echoing it into its text, a console message, a request URL) with "[secret]". |
| T-fill-11 | `log stream --process Koan` during all of the above; ⌘Q with a verify prompt waiting | No CHECK/DCHECK, no crash; nothing secret in the log. |
