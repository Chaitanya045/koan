# Koan vs Zen

How Koan compares with Zen, feature by feature. "Same" means it behaves the
way Zen does; "Different" says how and why; "Missing" means Koan doesn't
have it yet.

Koan's engine is Chromium, so everything about rendering, web platform
features, DevTools and extensions is Chrome's, not Firefox's. That is the
point of Koan.

## Layout and look

Zen's own library sprites, the 87 Space icons and web pages' icons aren't ported yet. |
| Vertical tabs in a sidebar | Same | Upstream Chromium vertical tabs, on by default. |
| Page as a floating rounded card | Same | |
| Sidebar and toolbar on one surface | Same | |
| Single-toolbar layout (address in the sidebar), the default | Same | Sidebar top row: toggle, back / forward / reload (plus Chromium's tab groups / tab search); URL pill below (sidebar width less 16, 36 high, radius 14, the Essentials tiles' tint, lighter on hover, no border): the site's favicon (opens the site panel), the host in 13.75pt medium, the copy-URL button on hover. No Chromium page actions (site settings, install, star) in the pill or while editing in it. |
| Window buttons hidden until the pointer reaches the top edge (single toolbar), Linux and Windows | Same | (Not on macOS, see below.) The page starts 8px below the window top; the strip with the frame's buttons opens on hover and pushes the page down, like Zen's. Buttons on the sidebar's side stay in its top row, as Zen places them (`ZenVerticalTabsManager._updateEvent`). Where compact mode hides the toolbar, the buttons come with the revealed toolbar. |
| Window buttons (traffic lights) on macOS | Partial | AppKit's buttons, **always visible** in the sidebar's top row (Zen on macOS doesn't hide them: `zen.view.hide-window-controls` is for other platforms), centred 22pt from the top in a 44pt row (Zen's 38pt row with 3pt margins), followed by the sidebar toggle and the navigation buttons. They go with the sidebar only where it is hidden (compact mode): Zen's compact mode shows nothing in the top row, Koan keeps its header there (single toolbar) and shows the lights with it. The pointer at the window's top edge reveals nothing and moves nothing with the sidebar on the left and single toolbar (the default; where compact mode hides the toolbar without single toolbar, the top edge still slides the toolbar in and shows the lights with it, as before) (Zen: `actualWindowButtons` is a compact-mode hover element, so the lights come with the sidebar; #178 captures: no strip, the page card stays at y=8; the strip with the lights over the page was Koan's, as on other platforms, and is gone). With tabs on the right they stay visible at the window's left (Zen's don't hide either), in a strip above the page that stays open (44pt tall, so the page starts lower than Zen's, which is not measured). The pointer on them keeps the revealed toolbar open, and the peeked sidebar out (Zen's `onLeave` on macOS; a lock held while the pointer monitor sees the pointer on the lights, let go of 150ms after it leaves them, #124). Measured on a Zen 1.24b Mac: 14pt circles, centres x=19/42/65. Zen's mono window controls (`zen.widget.mac.mono-window-controls`, on by default): with the pointer away, the lights are three dots in the toolbox's text colour (8% light, 15% dark; radius 6pt, 7pt on macOS 26) at the buttons' centres, and AppKit's coloured buttons come back while the pointer is over them or the window has a sheet (`KoanMonoTrafficLightsView`; the view only stops drawing under the pointer, never hides, since a hidden view's tracking area ends the hover it shows the buttons for: that loop made them flicker right after launch; `scripts/e2e/lights_hover_steady.mjs` counts the changes under the real pointer). Not tested on a Mac yet. The lights' own positions are AppKit's: on the Mac (macOS 27) they measured x=19.8/42.8, y=18.8 before the 44pt row (Zen: 19/42, y 22); Koan doesn't move them (Chromium's figures, 12,10 62x18, are for macOS 26: pitch 20 there). The sidebar toggle's x (Chromium's caption width, about 76) is not matched or checked on screen yet. The navigation buttons are Zen's 31x29 with no gap (31pt apart, #123); Zen right-aligns them 6pt from the sidebar's edge (sidebar width - 99/-68/-37), Koan 12pt (the header's inset, upstream's `kVerticalTabStripHorizontalPadding`), so they sit 6pt further left than Zen's. |
| Native fullscreen on macOS (top-edge reveal, no traffic light gap) | Partial | Koan's own layout stays in fullscreen, as in Zen: with single toolbar (the default) or compact mode hiding the toolbar, nothing of Chromium's top chrome is revealed from the top edge (no toolbar, no bookmarks bar: Chromium's fullscreen toolbar style is "none", see `HidesFullscreenTopChrome()`), but AppKit's own title bar strip (about 32pt, with the traffic lights, red at x≈16) slides in with the menu bar at the top edge, compact mode on or off (#178 captures of Zen; `ShowFullscreenTitlebar()`); the sidebar's top row has the toggle first, then back / forward / reload, and its URL pill opens the URL bar over the page; the menu bar and that strip reappear at the top edge. The content card stays (the usual gutter and radius; with compact mode on and no split view, Zen's `zen.view.borderless-fullscreen`: no gap and no radius, the page at (0, 0) filling the screen, and the pointer at the screen's edge reveals a hidden sidebar or toolbar, watched by the compact controller since the page covers every view). With multiple toolbars ("Sidebar and Top Toolbar") the toolbar stays above the page, next to the sidebar, as in a window: Zen on macOS keeps its toolbars in fullscreen (Firefox's mac default `browser.fullscreen.autohide` false, `defaults/preferences/firefox.js`; Zen's compact-mode CSS is gated on `inDOMFullscreen` only, `src/zen/compact-mode/zen-compact-mode.css:47`, and its toolbox doesn't move for the menu bar, `browser-fullScreenAndPointerLock-js.patch`), so Chromium's immersive mode leaves the top container in the window (`koan::KeepsTopContainerInFullscreen()`, the `browser_view.cc` hook) and View > Always Show Toolbar in Full Screen has nothing to choose (hidden, its command ignored). The 1 px line Chromium's fullscreen layout puts under a shown toolbar (`kFullscreen` window state) is not measured yet. (Zen's "Collapsed Sidebar" layout is not offered, see the layout row below.) Missing: the camera notch strip (Zen paints it black and empty; here AppKit's), the lights' and row's exact positions in fullscreen (not measured against Zen). Not tested on a Mac yet. |
| Bubbles about the page (permission prompts, page info, the bookmark bubble, downloads) in single toolbar | Partial | They point at the URL pill's site icon, as Zen's at the identity box (Chromium's anchor is the hidden toolbar). With the sidebar hidden by compact mode, at the header's buttons; with compact mode hiding just the toolbar, the toolbar slides in and stays until the bubble closes. A download no longer opens the downloads panel by itself (Zen's `alwaysOpenPanel` is off; the settings toggle still turns it on). The permission icon (the location bar's own, red while the camera, microphone or location is in use) shows next to the site icon, also for a quiet request, with its tooltip; Zen's identity box also opens the permission popup from that icon, here it opens page info. Not tested on a Mac yet. |
| Page (video) fullscreen on macOS | Partial | Koan is suspended, as in Zen (`:not([inDOMFullscreen])`): the page fills the screen with no card gap or radius, compact mode's edges and the URL bar do nothing, and nothing stays revealed after it (Zen's `_clearAllHoverStates`). The mode itself stays on, so nothing is reparented for every video. Hands-on on c157: nothing slides in at either edge, no gap or radius, Esc restores; ⌘L or Alt+F in a page's fullscreen reveal nothing either (re-tested after review). |
| Reserved shortcuts in native fullscreen on macOS (⌘T, ⌘W, ⌘N, tab switching) | Partial | A page that handles those keys doesn't get them in fullscreen either, as in a window (Chromium reserves them only while its toolbar shows, which in Koan's fullscreen it never does; Koan's hook counts the hidden toolbar as showing). The other shortcuts (⌘L, ⌃⌘F ...) are not reserved even in a window: a page can swallow them there too, in Chromium as in Firefox. In a page's own fullscreen Chromium's rule stays (a page may hold the keyboard). |
| ⌘Q on macOS asks before quitting | Different | Zen asks with a dialog on ⌘Q (`browser.warnOnQuitShortcut`, true in its shipped defaults). Koan keeps Chromium's "Hold ⌘Q to Quit": `browser.confirm_to_quit` is on by default (`chrome/browser/ui/cocoa/confirm_quit.cc`, Settings > Appearance > "Warn before quitting"), so a tap of ⌘Q shows the hold panel and does not quit, while a held ⌘Q (about 1.5 s) or a double tap quits; the app menu's Quit quits at once (it isn't keyboard-initiated). Turning "Warn before quitting" off makes a tap quit. Zen's dialog is not implemented. |
| Bookmarks bar | Same | Off by default, as Zen's bookmarks toolbar (`browser.toolbars.bookmarks.visibility` never), also on the new tab page and after importing bookmarks (an import turns Chromium's own setting on, which Koan ignores). Koan's settings (Look and Feel > Appearance) or ⇧⌘B (View > Always Show Bookmarks Bar, Zen's Ctrl+Shift+B / View > Toolbars) turn it on: below the toolbar with Sidebar and Top Toolbar; with Only Sidebar in Zen's top bar above the page (34 px, `vertical-tabs-topbar.inc.css`, `zen-has-bookmarks`), beside the sidebar; in macOS fullscreen too. Different: in compact mode with Only Sidebar Zen hides that top bar until the pointer is at the top edge, Koan keeps it docked; while the URL bar floats the bar is out of sight (the top container is the URL bar's card); Zen's top bar drags the window; whether Koan's empty bar does is a Mac step. |
| Bookmarks per Space (the bookmarks toolbar and menus show the active Space's and the unassigned ones) | Missing | It needs Spaces with an id shared by every window (Zen's window sync, not built yet). Koan's Spaces belong to one window. |
| Multiple-toolbars layout | Same | Ctrl+Alt+B (Zen sets this in Settings). |
| Collapsed-sidebar layout (icons only, expands on hover) | Missing | Not offered for now. Koan owns the sidebar's state (#154, `KoanVerticalTabsPolicy`, hook in `VerticalTabStripStateControllerImpl`): the sidebar is always expanded (Zen's 230 pt, 163 to 500 when dragged), and "collapsed" only means that compact mode hides it; that is never saved. Chromium's 56 px icon rail is unreachable (drag, keyboard resize, the sidebar button, ⇧⌘L, the View menu, an old profile or window, chrome://settings). Zen's layout would come back as its own Koan state with a Koan toolbar, not as Chromium's rail. |
| Tabs on the right (`zen.tabs.vertical.right-side`) | Same | Sidebar context menu, and Settings > Look and Feel > Vertical Tabs. The whole window is mirrored, including the sidebar's top row, its resize edge and the compact-mode reveal edge. Tabs themselves keep their left-to-right layout, as in Zen. Windows without Koan's sidebar (horizontal tabs, popups, apps) aren't mirrored. The setting is logical, like the rest of the UI: in a right-to-left UI it puts the sidebar on the left. |
| Dragging the sidebar's edge closed hides it | Same | Turns compact mode on with the sidebar hidden, and shows Zen's "Sidebar hidden! Use Ctrl+S to bring the sidebar back" toast once (with the compact mode shortcut as set; ⌘S on macOS). Leaving compact mode brings the sidebar back at its width. With "Hide toolbar" chosen, the drag switches compact mode to hiding both, so that the sidebar does hide (Zen just turns compact mode on, which there hides only the toolbar). |
| Toolbar context menu on the sidebar | Same | Compact Mode submenu (just the toggle with single toolbar, as in Zen) and Tabs on the right. Zen's other entries (customize toolbar, ...) don't apply. |
| Sidebar tab list: "+ New Tab" row above the tabs, tab rows, close button on hover | Same | The row opens the tab at the top of the Space, as Zen does with its New Tab button on top; Chromium's "+" below the tabs is hidden. Rows are 36px with a 14px radius, Zen's selected (white at 80%, 18% in dark mode) and hover colours, a 16px favicon 10px before the title. Zen's faint shadow under the selected tab isn't drawn. Ctrl+T opens the URL bar instead (see URL bar); with replace-newtab off, it opens the tab at the end. |
| Separator above the tabs with **Clear** on sidebar hover | Same | Shown while the Space has unpinned tabs. Also in compact mode's revealed sidebar, as in Zen (Koan hid it there because compact mode keeps Chromium's strip "collapsed"; Zen hides Clear only in its icons-only sidebar, which Koan's doesn't have; browser test `CompactModeRevealShowsTheClearRow`). Clear keeps the selected and audible tabs like Zen's, keeps the Space (an emptied one shows its hidden empty tab, no row, as Zen's; Clear never closes the empty tab) and Ctrl+Shift+T reopens what it closed, the last closed tab per press. Zen also keeps tabs in Picture-in-Picture or sharing camera/mic; Koan doesn't check those yet. |
| "Tabs Closed!" toast | Same | Top right (top left with tabs on the right, as in Zen), Zen's look; spring animation approximated with an ease-out scale. |
| Sidebar width 163–500 px, drag to resize | Same | Upstream resize handle with Zen's limits (Chromium's 126–400 px with the Koan sidebar off; a saved width is clamped to whichever applies). |
| Default look | Different (deliberate, 2026-11-11) | shadcn/ui's design system (dark, near-black, Geist) is the default look; Zen's colours (Zen 1.24b, gradient themes, glass) as Koan's token set are the second look: Settings > Look and Feel > Look (#48). Behaviour, layout and shortcuts stay Zen's in both. `koan.look.style` defaults to `shadcn`: a profile that never chose a look gets shadcn, one that picked Zen keeps it. |
| Theme follows the system light/dark mode | Same | In the Zen look. The shadcn look is dark by default; its Mode can be Light or Automatic. |
| Thin overlay scrollbars, shown while scrolling | Same | Chromium's overlay scrollbars, on by default on Linux in Koan. Zen follows GTK's overlay-scrolling setting ("Always Show Scrollbars" in GNOME's accessibility settings); Koan always overlays for now (#30). For classic scrollbars, start Koan with `--disable-features=OverlayScrollbar`. Comparison: `screenshots/scrollbars-zen-vs-koan.png` (Zen left, Koan right, while scrolling). |
| Gradient theme picker | Same | Zen's panel (`ZenGradientGenerator.mjs`) re-implemented in Views with Zen's formulas and constants: colour field with up to 3 dots, harmonies (Complementary, Split, Analogous, Triadic, Floating), the 5 preset pages, wave opacity slider (0.30-0.80 on macOS, 0.25-0.80 elsewhere, default 0.5, a haptic tick at every tenth on macOS), 16-step grain dial with Zen's `grain-bg.png` (a haptic tick per step on macOS, the grain fading to a new strength over 0.2 s), scheme buttons. An inactive translucent window is flat and opaque in `InactiveCaption` (macOS's window background colour), with no theme. On macOS the panel is Zen 1.24b's 380×514: Zen's macOS sizes in rem (6rem dial, 2rem from the slider), and a chrome rem there is Firefox's `message-box` font, `NSFont.smallSystemFontSize` (11px). Its icons (scheme buttons, colour actions, page arrows) are Lucide look-alikes from #110's set: Zen's are Nucleo icons, which can't be redistributed. The gradients belong to the Zen style; the shadcn style is flat. |
| Theme picker from the keyboard and screen readers | Different | Koan addition (Zen's panel is mouse-first): Tab reaches the colour field (Enter adds a colour, the arrows move the big dot, Shift for bigger steps, Delete removes it), the preset swatches (one tab stop, the arrows move between them), the opacity slider and the grain dial (sliders for assistive tech; arrows, Home, End). |
| Adjusting the glass | Different | Zen's opacity slider (per Space, 0.30 to 0.80 on macOS) sets how much of the blur shows, as in Zen. On a translucent window Koan's slider goes on to 1: above Zen's 0.80 the opaque paint fades in until the blur is covered, and the slider works for the default theme too (from Zen's default 0.5 on). Koan addition, for an opaque end. |
| Space themes and Chrome themes | Same | Zen disables lightweight themes (`zen.theme.disable-lightweight`). Koan windows ignore a Chrome Web Store theme's images and colours (web apps keep theirs), so Space themes and Koan's look stay; the theme stays installed. chrome://settings's Theme row still links to the Web Store (follow-up, audit T4). |
| Gradient behind sidebar, toolbar and page margin | Same | Zen's `getGradient()` layers, painted with Skia (premultiplied CSS interpolation) over the whole window. Zen gives the top toolbar (multiple-toolbars layout) its own gradient, which differs only for two-colour themes; Koan paints one gradient across the window. |
| Theme decides light/dark and accent of the window | Same | Zen's `shouldBeDarkMode()` and `getAccentColorForUI()` set the window's colour mode and accent, and Chromium's and Koan's colour IDs follow. | Custom colours in the picker | Same | Hex input with opacity, list with remove; hidden by default like Zen (`koan.theme.gradient.show_custom_colors`). Zen uses a colour input; Chromium Views has none, so it is a hex text field. |

| Zen | Koan | Notes |
