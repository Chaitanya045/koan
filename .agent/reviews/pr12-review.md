## PR 12 review — Open Glance on Alt+click

Verified against Chromium 158.0.8111.0 (`~/work/koan/chromium/src`).

**What checks out:**

- **NEW_POPUP → OpenURLFromTab trace (a):** anchor click → `HTMLAnchorElementBase::HandleClick` → `NavigateToHyperlink(NEW_POPUP)` → `RenderFrameImpl::OpenURL` (content/renderer/render_frame_impl.cc:6114, disposition mapped at :6134 via `NavigationPolicyToDisposition`, render_frame_impl.cc:1284 `kNavigationPolicyNewPopup → WindowOpenDisposition::NEW_POPUP`) → `FrameHost::OpenURL` → `BrowserWebContentsDelegate::OpenURLFromTab` (patches/chrome/browser/ui/browser_web_contents_delegate/browser_web_contents_delegate.cc.patch:546) → `MaybeOpenGlance`. Sound.
- **No other NEW_POPUP producer (a):** in stock blink nothing sets `kNavigationPolicyNewPopup` for clicks (navigation_policy.cc:52–81 only returns CurrentTab/SplitView/NewBackgroundTab/NewForegroundTab/NewWindow/Download). `window.open()` popups go through `RenderFrameImpl::CreateNewWindow` (render_frame_impl.cc:7065, mojo `FrameHost::CreateNewWindow`), not `OpenURLFromTab`, and context-menu opens are browser-initiated (`is_renderer_initiated` false) — the browser-side guards are correct.
- **`<a download>` same-origin (a):** honored — html_anchor_element.cc:527–539 calls `HandleDownloadAttribute` when the policy is not Download and the content is readable; the e2e covers it.
- **Feature propagation to renderers (b):** fine. `ChildProcessLauncherHelper` → `variations::PopulateLaunchOptionsWithVariationsInfo` (content/browser/child_process_launcher_helper.cc:121) → `FieldTrialList::PopulateLaunchOptionsWithFieldTrialState` (base/metrics/field_trial.cc:704–721) appends `--enable-features`/`--disable-features` from the browser's command-line feature overrides to every child process, and trial-based state flows through the shared-memory allocator (`InitFromSharedMemory`). `chrome://flags` and command-line overrides reach the renderer's `IsGlanceEnabled()`.

### Findings

- **should-fix** — patches/third_party/blink/renderer/core/loader/navigation_policy.cc.patch: upstream's synthesized-event guards don't cover the new policy. `NavigationPolicyFromEvent` (navigation_policy.cc:137–162) downgrades synthesized `kNavigationPolicyDownload` → CurrentTab ("No downloads from synthesized events without user intention"), likewise NewBackgroundTab (tab-unders) and SplitView — but there is no guard for `kNavigationPolicyNewPopup`, which only this patch can produce. Failure scenario: a script dispatching `new MouseEvent('click', {altKey: true, bubbles: true})` on an anchor gets event_policy = NEW_POPUP with input_policy = CurrentTab; no guard matches, and the untrusted renderer-initiated NEW_POPUP (correctly rejected by `MaybeOpenGlance`) falls through to default handling — a **popup window opens**, where stock Chromium navigates the current tab. Fix: mirror the existing guards, e.g. `if (event_policy == kNavigationPolicyNewPopup && input_policy != kNavigationPolicyNewPopup && !UIEventWithKeyState::NewTabModifierSetFromIsolatedWorld()) return kNavigationPolicyCurrentTab;`.
- **should-fix** — docs/USAGE.md claim "links with a `download` attribute still download" is only true for content-readable (same-origin) links. Failure scenario: Alt+click a **cross-origin** `<a download>` link: html_anchor_element.cc:527 skips the download block (`CanReadContent(cross-origin)` is false) and `NavigateToHyperlink` runs with the new NEW_POPUP policy → trusted renderer-initiated NEW_POPUP → `MaybeOpenGlance` opens the file in the Glance card. Stock Chromium Alt+clicks it into a download (policy `kNavigationPolicyDownload`). Same pattern in mathml_anchor_element.cc:135–146. Fix: in the anchor click handlers, keep the download path when the Glance popup policy and a `download` attribute coincide, or scope the docs claim.
- **should-fix (lower)** — `window.open(url)` (no popup features) executed inside an Alt+click handler now opens a **popup window** instead of a foreground tab. `NavigationPolicyForCreateWindow` (navigation_policy.cc:163–189) returns `user_policy` verbatim when it is not CurrentTab/Download/NewWindow; with the patch the current event's policy is NEW_POPUP, so `CreateNewWindow` (create_window.cc:323, disposition at render_frame_impl.cc:7100) is NEW_POPUP → stripped popup. Stock: `user_policy == kNavigationPolicyDownload` → falls back to `app_policy` (NEW_FOREGROUND_TAB). Fix: treat the new popup user-policy like the download case there (fall back to `app_policy`).
- **nit (latent)** — linking `//koan/browser:features` (a plain `source_set`, src/browser/BUILD.gn:7–14) into blink core's component duplicates the `base::Feature kKoanGlance` object into two components. `base::FeatureList::CheckFeatureIdentity` (base/feature_list.cc, `GetOverrideStateImpl`) DCHECKs — "…built into multiple components (shared libraries) without a corresponding export statement" — if two same-named Feature objects are ever queried in one process. Today each copy is only queried from its own context (blink core in renderers, browser code in the browser process), so nothing fires and the e2e passes, but any future renderer-side or browser-process query of the other copy trips the DCHECK. Fix: make the target a `component()` with exported symbols, or pass the flag into blink via renderer prefs instead of linking the target.
- **nit** — stale comment in patches/chrome/browser/ui/browser_web_contents_delegate/browser_web_contents_delegate.cc.patch:546 still says "Shift+click opens the link in a floating card instead".
- **nit** — `NavigationPolicyFromEventInternal` also runs for KeyboardEvent (button=0) and GestureEvent, so Alt+Enter on a focused link (and an Alt+touch-tap) now Glance; stock Chromium downloaded on the Enter path. Undocumented in USAGE.md; probably fine, worth a doc line at most.

**Verdict:** the design and the NEW_POPUP contract are correctly traced end-to-end; fix the missing synthesized-event guard and the cross-origin `download` case before merge.
