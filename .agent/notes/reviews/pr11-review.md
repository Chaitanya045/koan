## PR 11 review — Match Zen's keyboard shortcuts

Verified against Zen's `ZenKeyboardShortcuts.mjs` (version 21, Linux accel=Ctrl) and Chromium 158.0.8111.0.

**Bindings vs Zen (check a):** All explicit Zen defaults match: compact toggle Ctrl+S, peek sidebar Ctrl+Alt+S, save page Ctrl+Alt+Shift+S (Zen's `correctDefaultShortcut`), workspace Ctrl+Alt+←/→, split Ctrl+Alt+G/V/H/U, copy URL Ctrl+Shift+C and Ctrl+Shift+Alt+C (v6/v8), pin Ctrl+Shift+D (v10), glance expand Ctrl+O (v10), close unpinned Ctrl+Shift+K (v13), new window Ctrl+Shift+N (v15), inspector Ctrl+Shift+L (moved key on `key_inspector`), library Alt+Shift+L (v21). The dual `VKEY_8`/`VKEY_MULTIPLY` binding for Ctrl+Shift+* is a reasonable rendering of Zen's `key="*"`. No mismatches.

**Accelerator precedence (check b): correct, contrary to my initial suspicion.** `KoanShortcutController::OnAddedToWidget` runs from the `ViewObserver::OnViewAddedToWidget` notification, which `View::PropagateAddNotifications` fires *after* `AddedToWidget()` returns (ui/views/view.cc:3529–3533), i.e. after `BrowserView::AddedToWidget()` → `LoadAccelerators()` (chrome/browser/ui/views/frame/browser_view.cc:5085, 5704) registered BrowserView's command accelerators. Normal-priority registration is `targets_.push_front` and `TryProcess` iterates front-first (ui/base/accelerators/accelerator_manager.cc:144, 170–179), so Koan is tried first and falls through when `Run` returns false (e.g. Ctrl+O with Glance closed → IDC_OPEN_FILE). Non-reserved browser commands reach this path only after the renderer declines (browser_view.cc:3316–3322 `NOT_HANDLED_IS_SHORTCUT` → `unhandled_keyboard_event_handler_` → `focus_manager->ProcessAccelerator`), so pages get Ctrl+S first, as documented. Lifetime (check c): `DestroyFor` unregisters Koan's accelerators first; `shortcuts_` declared last → destroyed first while the controllers it calls are still alive. Correct.

### Findings

- **should-fix** — src/browser/ui/views/koan_compact_mode_controller.cc:338–340 (`OnSidebarHotZoneHovered`) vs koan_compact_mode_controller.cc:163–182 (`PeekSidebar`): both share the single `sidebar_lock_` without ownership tracking. Failure scenario: user presses Ctrl+Alt+S (peek acquires the lock, 3 s grace), then sweeps the pointer across the left-edge hot zone and off again — `OnSidebarHotZoneHovered(false)` unconditionally does `sidebar_lock_.reset()`, so the sidebar collapses instantly and the grace period is defeated (the peek timer then stops itself on `!sidebar_lock_`). Inverse: pointer parked on the hot zone (lock held by the hover path) + Ctrl+Alt+S, then peek expiry `sidebar_lock_.reset()` at line 180 drops the hot zone's lock while the pointer is still on the hot zone. Fix: keep separate lock instances (e.g. `peek_lock_` vs `hover_lock_`), or have `OnSidebarHotZoneHovered(false)` only reset the lock it acquired.
- **should-fix (low; only under `--disable-features`)** — src/browser/ui/views/koan_shortcuts.cc:210–244: `Run()` dispatches `kToggleCompactMode`/`kNewWorkspace`/`kWorkspaceForward`/`kWorkspaceBackward` with no feature gate, where previously `KoanCompactModeController::CanHandleAccelerators()` required `features::IsCompactModeEnabled()` and `KoanWorkspaceController::CanHandleAccelerators()` required `IsEnabled()`. With `KoanWorkspaces` off, Ctrl+Alt+N still creates a tab group and enters focus mode (`KoanWorkspaceController::CreateWorkspace`, koan_workspaces.cc:336–347) while `InstallSwitcher()` never ran — an invisible workspace state with no UI to manage it. `CanHandleAccelerators()` (koan_shortcuts.cc:186) now only checks `GetIsNormalType()`. Features are enabled by default, so this only bites with flags off. Fix: check the relevant feature in `Run()` (or in `CanHandleAccelerators` per-action).
- **nit** — src/browser/ui/views/koan_shortcuts.cc:220: Zen's `cmd_zenToggleLibrary` toggles the full library (bookmarks + history + synced tabs); `kLibrary` maps to `IDC_SHOW_HISTORY` only. Documented as-is in docs/USAGE.md, so presumably intentional.

**Verdict:** bindings and precedence are right; two should-fix issues (hot-zone lock stealing, missing feature gating) but nothing blocking.
