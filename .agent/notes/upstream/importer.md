# Upstream audit: import from other browsers (#348)

Scope: what Koan's welcome import step and Chromium's import dialog list and import on macOS, and how Koan adds Zen
(and other Firefox-based browsers), Arc and Chrome (and the other Chromium-based ones). Pristine source:
`git -C ~/work/koan/chromium/src show HEAD:<path>` (Chromium 158). Zen 1.24b for behaviour:
`.cache/zen-desktop-1.24b/src/zen/migration/` (ZenProfileMigrators, ZenMigrationUtils), `src/zen/welcome/ZenWelcome.mjs`,
`src/browser/components/migration/*.patch` (read only, MPL).

## 1. Chromium 158's importer on macOS

| # | Piece | What it does (Mac) |
|---|---|---|
| I1 | `ImporterType` (`components/user_data_importer/common/importer_type.h`) | `TYPE_FIREFOX` 2, `TYPE_SAFARI` 3 (Mac), `TYPE_BOOKMARKS_FILE` 5; IE 0 and Edge 6 are Windows-only. No Chrome/Chromium type on any platform. |
| I2 | `ImporterList::DetectSourceProfiles` (`chrome/browser/importer/importer_list.cc`) | on the thread pool: Safari (`SafariImporterCanImport(~/Library)`) and Firefox (default browser first), then the interactive bookmarks file. The only list: the import dialog (`ImportDataHandler`), first-run auto-import (`first_run.cc`, profile 0, only with initial prefs asking for it) and Koan's welcome use it. |
| I3 | Firefox detection (`firefox_importer_utils*.cc`) | `GetProfilesINI()` = `DIR_APP_DATA/Firefox/profiles.ini` (`~/Library/Application Support/Firefox`); `GetFirefoxDetailsFromDictionary` lists `Profile0..N` (contiguous), relative paths against *Firefox's* ini folder (so it can't be pointed at Zen's); a profile is listed only if `compatibility.ini`'s `LastVersion` is 48 or more (Zen writes its own version, `1.23.3b_...`, which reads as 1). Name from `application.ini` (Firefox / Iceweasel). |
| I4 | What the Firefox importer brings on macOS | `HISTORY`, `FAVORITES`, `AUTOFILL_FORM_DATA`; **no `PASSWORDS`**: NSS can't be loaded into the signed process (comment in `DetectFirefoxProfiles`; `ImportPasswords` is `!IS_MAC`). Search engines and the home page are not offered. It reads only `source_path` (copies of places.sqlite, favicons.sqlite, formhistory.sqlite) and `app_path` for the default bookmarks to skip (empty: nothing skipped). |
| I5 | `ExternalProcessImporterHost` (`external_process_importer_host.cc`) | `StartImportSettings`: Firefox lock check (`FirefoxProfileLock` on `source_path/.parentlock`; a dialog asks to close the browser, or a headless import cancels), waits for the bookmark model and search engines, then `LaunchImportIfReady` starts the utility process (`ExternalProcessImporterClient`, `ProfileImport` mojo, kNoSandbox) with an `InProcessImporterBridge` to the `ProfileWriter`. |
| I6 | The utility process side (`chrome/utility/importer/importer_creator.cc`) | `CreateImporterByType`: bookmarks file, Firefox, Safari (Mac); anything else `NOTREACHED()`. The IPC traits (`profile_import_process_param_traits_macros.h`) take only `TYPE_UNKNOWN..TYPE_BOOKMARKS_FILE` off Windows. |
| I7 | A Chromium-profile importer | none on macOS in 158. (`edge_importer_win.cc` is old Edge's ESE database, Windows.) |
| I8 | The import dialog (`chrome/browser/resources/settings/people_page/import_data_dialog.*`) | a `<select>` of `importer_name` (+ profile), the first selected; checkboxes per `services_supported`. On macOS a `<select>` opens a native NSMenu: no icons possible without changing upstream's template. |
| I9 | `ProfileWriter` | bookmarks: straight onto an empty bookmarks bar, else into an "Imported from …" folder (the name the importer gives); history via `AddPagesWithDetails` with an imported visit source (all imported sources are treated alike, `visit_database.cc`); passwords to the profile store if saving is on. |
| I10 | `LogImporterUseToMetrics` | a switch on the type, no default: an unknown value counts as unknown. |

## 2. Decisions

| # | Upstream piece | Decision | Koan |
|---|---|---|---|
| D1 | The source list (I2) | **reuse + one hook**: `koan::importer::AddSourceProfiles(locale, profiles)` at the end of the worker, before the bookmarks file: Koan's sources first (the most recently used browser first, as Zen's welcome sorts by last use), then upstream's, then the welcome's pick moved to the front (`SetPreferredSource`). Everything that lists (dialog, welcome, auto-import) sees the same list. | `importer_list.cc.patch`, `koan_import_sources.cc` |
| D2 | Firefox detection (I3) | **redirect, no patch**: Koan parses Zen's (Floorp's, LibreWolf's, Waterfox's) profiles.ini itself with upstream's `DictionaryValueINIParser`: profiles with a places.sqlite, the install's `Default` (else `Default=1`) first, a single profile unnamed (as upstream). No version cutoff (Zen's version isn't Firefox's). | `ParseProfilesIni` |
| D3 | The Firefox importer (I4, I5) | **reuse**: a Zen source is `TYPE_FIREFOX` with Zen's profile folder, so the lock check, the utility process and the writer are upstream's. Passwords stay off on the Mac, as upstream decided (USAGE.md: Zen's CSV export). | — |
| D4 | No Chromium importer (I6, I7) | **override at one decision point**: `LaunchImportIfReady` asks `koan::importer::MaybeStartChromiumProfileImport` first; for a Koan Chromium source it reads the profile on the thread pool and writes through an `InProcessImporterBridge`, telling the host the progress as the utility process would. The type is `kChromiumImporterType` (7), never sent over IPC (I6's traits would reject it). Not a utility process importer: that needs patches to the enum, the IPC traits, `importer_creator.cc` and `importer_uma.cc` (its switch has no default), four hooks instead of one. | `external_process_importer_host.cc.patch`, `koan_chromium_profile_importer.cc`, `koan_chromium_profile_reader.cc` |
| D5 | Chromium profile layout | Local State's `profile.last_used`, `profiles_order`, `info_cache` (names); per profile `Bookmarks` + `AccountBookmarks` (JSON), `History` (`urls`), `Login Data` + `Login Data For Account` (`logins`), read from copies (the browser may hold them). Passwords: os_crypt's macOS scheme ("v10", PBKDF2-SHA1 of the "<Browser> Safe Storage" secret, "saltysalt", 1003, AES-128-CBC, 16-space IV), the secret from `crypto::apple::KeychainV2::FindGenericPassword` (macOS asks the user), asked only when the profile has a Login Data. Digest/federated logins, `chrome://` history and undecryptable passwords are left out. | reader |
| D6 | Arc's sidebar (`Arc/StorableSidebar.json`) | Zen turns it into Spaces, pinned tabs, folders and Essentials (ZenMigrationUtils' `parseArcSidebar()` / `applyArcSidebar()`). Koan (#363) reads the same plan (`ParseArcSpaces`, `koan_imported_spaces.cc`: the "global" container's Favorites (`topAppsContainerIDs`), each Space's pinned container with its folders and split views, title/"Personal"/"Space <n>", `customInfo.iconType` emoji, `customInfo.windowTheme` colours as Zen's theme object) and, with the **Spaces and pinned tabs** item, makes Koan Spaces (D10). Without it, the plan as bookmarks (a folder per Space, "Favorites"), as #348 did. **Revised by #481 (2026-11-27): a profile per Arc profile**, as Zen (`containerIdForArcProfile()`): each Space and Favorite carries its Arc profile (`ImportedSpace::profile`, `ImportedItem::profile`: none for `Default`, else Local State's `info_cache` name, else the folder); `ImportSpaces()` finds the user container (`koan.containers.user`, #318) of that name or makes one (`AddUserContainer`, Firefox's colour order), sets it as the Space's `container` and puts each tab's `koan.container` session data, so the unloaded tab restores into it (`SiteInstanceForRestoredTab`). Arc's default profile is Koan's Default (no container). Zen's import (no profile in the plan) leaves the Space's container as it was. The first Space still takes the untouched active Space, now with its Arc profile (Zen skips that for a container Space and makes a new one; Koan's empty tab follows the container, so no stray Space is left). Favorites keep their own profile, also when they don't fit and go to the first Space. Cookies are never read: the dialog's last step says to sign in again in each (D15). | `ParseArcSpaces`, `ParseArcSidebar`, `koan_space_import.cc` |
| D10 | "Spaces and pinned tabs" (Zen's `ZEN_SPACES` resource, #363) | **extend, no new importer**: `koan::importer::kSpacesImportItem` (1 << 7, past `ImportItem::ALL`; never an `ImportItem`, never over IPC) in `services_supported` for Arc (a StorableSidebar.json) and Zen (a zen-sessions.jsonlz4) and in the items asked. The import hook (D4, now `MaybeStartKoanImport(source, items&, profile, ...)`) reads the plan on the thread pool and calls `koan::ImportSpaces()` (`koan_space_import.h`, views): Essentials while 12 fit (the rest pinned in the first Space), the first Space takes the window's untouched active Space, the others `CreateBackgroundSpace()` at the end, tabs `chrome::AddRestoredTab()` unloaded with Koan's pinned state (`KoanTabState`), folders `AddSyncedFolder()` (tabs join by their session data), at most 5 deep. Zen: the item is taken out of `items_` so Chromium's Firefox importer brings the rest in parallel; asked alone, Koan's in-process bridge is the whole import. Spaces alone are reported as `FAVORITES` (the dialog counts an import with no ended item as failed). | `koan_chromium_profile_importer.cc`, `koan_space_import.cc` |
| D11 | Zen's session file (`zen-sessions.jsonlz4`, Zen 1.24 `ZenSessionManager.sys.mjs`) | **read**: mozLz4 (`mozLz40\0`, LE size, one LZ4 block); Chromium 158 has no LZ4, so `koan_lz4.cc` decodes the block format (spans, no pointer arithmetic, 256 MiB cap). `spaces` (uuid, name, emoji icon (Zen's SVG icons dropped), theme object as Koan stores it), `tabs` (`pinned`; `zenEssential`; `zenWorkspace`; `groupId`; `_zenPinnedInitialState.entry` else the current entry; `zenStaticLabel`; empty, Glance and live-folder tabs left out), `folders` (tab groups: `parentId`, split views flattened into their folder, live and Essentials folders left out, loops broken). | `ParseZenSessions`, `ReadZenSpaces` |
| D12 | Settings > Import's checkbox (I8) | **hook, 4 small patches**: no extension point adds a checkbox to upstream's dialog. Template (one `settings-checkbox`, `koan.import_dialog.spaces`), the `BrowserProfile` type (`koanSpaces?`), the handler (`AddImportDialogItems` / `GetImportDialogItems`, `koan_settings_ui.h`), the settingsPrivate allowlist (`prefs_util.cc`). The welcome's import step shows the same option for Zen and Arc and sets the pref the dialog starts from. | REBASE.md row |
| D13 | Arc's link rules (Air Traffic Control, #481) | **read, assumed format**: `StorableLinkRouting.json` beside `StorableSidebar.json`, `{version, defaultDestination, rules: [{id, sourceComponents: [{id, componentType: {urlMatch: {_0: {contains: {}} \| {matches: {}}, _1: "<text>"}}}], destination: {space: {_0: <Space id>}} \| {littleArc: ...}}]}`. Not read from a real Arc install (none was available): taken from public readers of the file (Copper's PR 218 says it checked two real Arc folders, keys only; vane's issue 490 gives a sample); Koan accepts a Space id as a string `_0` or `_0.space._0` (readers differ), and "is" as `matches` or `isEqualTo`. Each rule with **one** URL condition (`contains` → Koan's contains, `matches` → equal-to) and a Space destination among the imported Spaces becomes a Space route (`koan.space_routing.routes`, #81) to that Space's name, after the user's routes, never twice; `defaultDestination` naming an imported Space becomes the links-from-other-apps default only while the user has none. Left out: Little Arc and "most recent Space" destinations (Koan's no-route already opens in the active Space), rules on the source app, `startsWith`, several conditions (their meaning together is unknown), Spaces not imported. Only with the Spaces item (the routes name Spaces). Zen's Arc import brings no rules. | `AddArcLinkRules`, `ImportSpaces` |
| D14 | Every Arc profile in one run (#481) | **Zen's "All profiles"** (`withAllProfiles()`): with two or more Arc profiles with data, `DetectSourceProfiles` lists Arc first as profile "All profiles" (`kAllProfilesName`, Zen's name; a longer one that said what one run brings was cut off in the dialog's `<select>`, so USAGE.md says it), its `source_path` the "User Data" folder (`IsAllProfilesPath`), then each profile. Its import reads every profile with data (`ChromiumProfilesWithData`): the Spaces of all, each in its profile (D6); bookmarks, history and passwords of all, since Koan's profiles share them (#318) anyway: bookmarks in a folder per profile (`in_toolbar` off, the profile's name first in the path: on an empty bar a folder each, else inside "Imported from Arc"), history and passwords together, one keychain prompt (one key per browser). Zen imports each resource per profile in turn the same way. | `koan_import_sources.cc`, `ReadProfile` |
| D15 | The import's last step (#481) | **hook, +4 lines in the D12 patches**: Chromium's success page has no Koan slot. Arc sources whose install has several profiles carry `kSpaceProfilesNote` (1 << 8, a `services_supported` bit, never an item asked); `AddImportDialogItems` sends `koanSpaceProfiles` (with `koanSpaces`) and the success page shows "If you brought your Spaces, they keep their separate profiles. Sign in again in each: logins don't come along." The dialog doesn't know whether the Spaces box was ticked at that point without reading the pref in the template, hence "If you brought your Spaces". | REBASE.md row |
| D16 | Platforms (#481) | Arc exists on macOS and Windows only. Koan's `SearchRoot()` is `~/Library/Application Support` on macOS and empty elsewhere, so on Linux (the Flatpak) no Koan browser is listed and the import step shows only Chromium's own; `--koan-import-test-root=<dir>` lists and imports a fixture folder on any platform (passwords from its `Keychain/` files). Arc for Windows' folder (`%LOCALAPPDATA%\Packages\TheBrowserCompany.Arc_*\LocalCache\Local\Arc`) is not searched: Koan has no Windows build. | `SearchRoot` |
| D7 | The dialog's `<select>` (I8) | **reuse**: names (and profile names) only; icons are the welcome's (`AppIconDataUrl`: NSWorkspace's icon of the app by bundle id, 64 px PNG data: URL; the page's CSP has no img-src limit). | welcome |
| D8 | The welcome's pick | **override**: the dialog opened on the first entry whatever was picked; now the pick is first (D1). | `KoanWelcomeHandler::HandleImport` |
| D13 | Linux (#493): Firefox detection (`firefox_importer_utils_linux.cc`: `$XDG_CONFIG_HOME/mozilla/firefox`, `~/.mozilla/firefox`, Snap, Flatpak), passwords through NSS (`nss_decryptor_system_nss.cc`, `readOnly`), os_crypt's Linux keys (`posix_key_provider.cc` "v10", `freedesktop_secret_key_provider.cc` "v11", `secret_portal_key_provider.cc` "v12") | **reuse + redirect, no new hook**: the search root is the home folder (`DIR_HOME`, the real one in a Flatpak), the table gives each browser its native folder and its Flatpak's (`~/.var/app/<id>`, the app's `config/` as its XDG_CONFIG_HOME), Firefox-based ones also their XDG folder; Arc and Dia left out. Firefox is in Koan's table on Linux (upstream's XDG check reads the sandbox's XDG_CONFIG_HOME in Koan's Flatpak), and upstream's copy of a profile Koan lists is dropped. Gecko passwords offered, as upstream offers Firefox's on Linux. Chromium keys: "v10" with the fixed key always, "v11" from the browser's own Secret Service item (`xdg:schema` + `application`, never unlocking a locked one) else its KWallet entry (only a running kwalletd; KWallet asks the user), read over a private session bus only when passwords are imported; "v12" can't be read (the portal binds it to that app). Upstream's `FreedesktopSecretKeyProvider` isn't reusable: its names are compile-time Chromium's and it creates the item when missing. Icons: the hicolor theme's files (the welcome's `AppIconDataUrl` reads them from a cache filled on the detection thread, so no IO on the UI thread). | `koan_import_sources.cc`, `koan_import_platform_linux.cc`, `koan_import_icons_linux.cc`, `flatpak/dev.koan.Koan.yml` |
| D9 | Tests reading real profiles | **lock**: `--koan-import-test-root=<dir>` replaces `~/Library/Application Support` and the keychain (`<dir>/Keychain/<item>` files); every test uses it; on Linux it replaces the home folder and the icon folders too. | `koan_switches.h` |

## 4. Tests

- Unit (`koan_unittests`): `koan_import_sources_unittest.cc` (profiles.ini, Local State, detection order and services, the hook and the welcome's pick), `koan_chromium_profile_reader_unittest.cc` (the key and a fixed "v10" vector from other code, Bookmarks JSON, Arc's sidebar, History, Login Data), `koan_imported_spaces_unittest.cc` (Arc's and Zen's plans, Arc's profiles and link rules, a folder loop, a mozLz4 file), `koan_lz4_unittest.cc` (vectors from the reference lz4, malformed blocks).
- Browser (`koan_browsertests`): `koan_import_browsertest.cc`: the list, the pick first, Zen through the Firefox importer, Chrome with its password, Arc's pinned tabs, only the items asked; Spaces offered by Zen and Arc only, Arc's and Zen's Spaces, Essentials, pinned tabs and folders, Zen's Spaces next to its bookmarks, and the imported (unloaded) tabs kept in `koan.workspaces.list` / `koan.folders.list`; Arc with two profiles (`KoanArcProfilesImportBrowserTest`: "All profiles" listed first, two Koan profiles made, the Spaces and Favorites in theirs, the routes and the external default, bookmarks per profile).
- Fixture: `src/test/data/arc_import/` (an Arc folder with two profiles, sidebar and link rules; structure only, made from the formats above, not copied from a real install) for hand tests with `--koan-import-test-root`.
- E2E (Mac suite): `scripts/e2e/import_sources.mjs`: the welcome's list with icons, the dialog on the pick, imports, and what landed (bookmarks, history, passwords pages).
